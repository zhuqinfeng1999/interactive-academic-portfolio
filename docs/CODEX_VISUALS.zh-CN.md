# 使用 Codex 设计科研交互动效

[English](CODEX_VISUALS.md)

优秀的主页动效不应只是“科技粒子背景”，而应该是一个被适度简化的科学模型：视觉元素有明确含义，鼠标/触摸操作对应可解释的变化，Canvas 外部还有简短文字帮助访客理解。

## 给 Codex 的必要信息

开始前提供：

1. 当前仓库和本指南；
2. 3–5 句研究简介；
3. 动效中应该出现的科学对象；
4. 交互需要解释的关系或过程；
5. 一到两个视觉参考（如有）；
6. 下述性能与设备约束。

不要只说“更科幻、更高级”。先要求 Codex 提出视觉假设并解释其科学含义，确认合理后再实现。

## 必须保持的技术接口

共享城市几何和四种 GPU 模式位于 `assets/js/spatial-cloud.js`，界面协调与 Canvas 2D 兼容渲染位于 `assets/js/spatial-world.js`。首页和 Explorer 先加载 GPU 模块，再加载场景控制器。修改时要求 Codex 保留：

- 通过 `[data-spatial-world]` 查找 Canvas；
- 实例继续暴露为 `canvas.spatialWorld`；
- `setMode(mode)` 能更新场景和按钮状态；
- 鼠标、触摸、点击和 resize 全部可用；
- 通过 `[data-world-title]`、`[data-world-detail]`、`[data-world-status]`、`[data-world-interaction]` 更新说明；
- `prefers-reduced-motion: reduce` 下仍有稳定且有意义的画面；
- 页面不可见时暂停或降低渲染频率；
- 在 390、768、1440 px 宽度下都清晰；
- 交互不能只依赖 hover；
- 不修改其他页面，也不移除模板来源链接。

性能目标：

- 普通集成显卡笔记本也能流畅运行；
- 动画循环中不持续创建无界对象；
- 合理限制设备像素比；
- 未经批准不加载网络 3D 模型或大型框架；
- 控制台无错误，页面无横向溢出。

## 推荐三阶段流程

### 第一阶段：只做概念

```text
阅读我的研究简介和 Spatialfolio 当前交互，暂时不要修改文件。
提出三个完全不同的视觉隐喻。每个方案说明：
1. 展示哪些科学对象；
2. 哪些状态随时间变化；
3. 鼠标移动代表什么；
4. 点击/触摸代表什么；
5. 不依赖 Canvas 内文字时如何让人理解；
6. 为什么它在科学上合理，而不只是装饰。
推荐一个方案，并指出最可能失败的地方。
```

### 第二阶段：实现

```text
在 assets/js/spatial-cloud.js（共享几何与四种 GPU 模式）中实现选定方案。
如需更改界面或兼容渲染，同步更新 assets/js/spatial-world.js。
保留 Spatialfolio 的公开接口、全部页面钩子、移动端行为、减少动画支持和
可见的模板署名。除非我明确批准，只使用原生 WebGL、Canvas 2D 和仓库内资源。
交互必须响应及时、科学含义清晰，并与深色青色视觉系统融合。
必要时同步修改模式按钮和状态说明。
```

### 第三阶段：对抗式验收

```text
分别以苛刻的交互设计师、领域研究人员和前端性能工程师身份审核结果。
测试桌面、平板、手机、触摸、减少动画和快速切换模式。
解释每个视觉元素的含义；删除任何没有合理含义的线、粒子、圆环和动画。
修复重叠、构图稀疏、跟手性差、运动过强、控件不清、控制台错误和页面溢出。
持续迭代直到全部通过，最后总结整套科学视觉语法。
```

## 世界模型 / 自动驾驶提示词

```text
把首屏重新设计为交互式世界模型。展示连贯的鸟瞰场景，包括静态地图结构、
已观测智能体、短历史轨迹和多条概率未来轨迹。鼠标移动用于移动局部检查窗，
显示占用、速度和不确定性；点击用于推进一个预测步或展开不同未来。
不要使用无意义光束或泛化的 lidar 扫描线。画面要在首屏右侧形成均衡密度。
统一颜色含义：青色=已观测结构，橙色=不确定未来，紫色=潜在假设，
浅绿色=当前选中预测。
```

## 医学图像分割提示词

```text
把首屏设计为三维医学分割浏览器。使用半透明轴向切片或抽象体数据，展示
两到三个在形态上合理的区域和不确定性轮廓。鼠标移动用于浏览深度，同时
保持空间上下文；点击用于切换预测、标注和不确定性。除非研究真实使用心电
时间信号，否则不要添加装饰性 ECG 线。配色应具有临床感但仍符合 Spatialfolio，
并确保仓库中不嵌入任何真实患者数据。
```

## 凝聚态物理提示词

```text
围绕倒空间或晶格模型重构首屏。展示有限晶格、具有物理意义的键，以及可控的
自旋、轨道或序参量纹理。鼠标移动用于施加局部场或在动量空间中移动；点击用于
切换实空间纹理、能带和 Berry 曲率（只有与我的研究一致时才使用这些量）。
统一编码符号与大小，避免随机粒子运动，并解释每个重复结构所对应的对称性。
```

## 多模态科学学习提示词

```text
把首屏设计为多模态推理系统。每种模态需要有不同的观测几何，然后展示证据如何
对齐到共享表示并回到任务预测。鼠标移动用于查看跨模态对应关系；点击用于关闭
一种模态并观察不确定性的变化。不要把融合简单画成任意线条汇聚到发光圆点。
布局必须让缺失模态鲁棒性和信息流变得可观察、可检验。
```

## 最终验收清单

- 初次访问者十秒内能描述动效想表达的概念；
- 每条长期存在的线、点、区域和动画都有研究含义；
- 鼠标响应及时但不抖动；
- 点击/触摸会触发容易发现的状态变化；
- 画面充分利用空间，但不与首屏文字重叠；
- 按钮名称准确预告切换后的画面；
- 状态文字用普通语言解释当前交互；
- 减少动画模式仍能传达核心概念；
- 手机控件不遮挡关键内容；
- Canvas 文字不是唯一的信息来源；
- 自动校验和浏览器控制台均无错误。

## 不应让 Codex 自动修改的内容

- 已核实的论文信息；
- 个人简介、求职状态和外部链接；
- 署名许可证和可见的模板来源链接；
- 无法从你提供资料中确认的领域结论。

把动效当作“具有行为的科学插图”，而不是屏保。
