# Customizing Spatialfolio

[中文版本](CUSTOMIZE.zh-CN.md)

This guide keeps customization deliberate. Finish the identity and data pass first, then tune visuals, and only then redesign interactions.

## 1. Prepare your content

Collect these before editing:

- preferred name, title, city and institution;
- a 50–90 word biography and a one-sentence research question;
- email, GitHub, Google Scholar, ORCID and LinkedIn URLs;
- current availability statement;
- complete publication metadata and verified links;
- 4–7 research directions with short descriptions;
- 2–6 projects with one clear artifact per project;
- a CV PDF, if you want a download button;
- images that you own or have permission to redistribute.

## 2. Replace identity placeholders

Search the repository for these strings:

```text
Your Name
YN
Your University
Your City
yourusername
hello@example.com
https://yourusername.github.io/
```

Update every HTML file, including metadata, canonical URLs and JSON-LD. The `YN` monogram can be any two short characters.

Do not forget:

- page `<title>` values;
- `meta[name="description"]`;
- Open Graph URL, title, description and image;
- schema.org `Person` data on the homepage;
- footer copyright text;
- social-profile URLs;
- email links and accessible labels.

## 3. Replace the structured research data

Edit `assets/data/research.json`.

### Research directions

Each domain needs a unique `id`, display number, title, kicker, description, image, atlas position and a list of publication IDs.

```json
{
  "id": "medical-imaging",
  "number": "01",
  "title": "Medical Imaging",
  "kicker": "Clinical evidence",
  "description": "Learning reliable representations from multimodal clinical images.",
  "image": "/assets/images/directions/medical-imaging.svg",
  "position": { "x": 18, "y": 25 },
  "publicationIds": ["your-paper-id"]
}
```

If you change domain IDs, also update the `edges` array and the central-node ID in `assets/js/research-atlas.js`.

### Publications

Use stable, lowercase IDs. Every author is an object so your name and equal-contribution marks can be styled consistently.

```json
{
  "id": "your-paper-id",
  "year": 2026,
  "venue": "Full Venue Name",
  "venueShort": "VENUE",
  "type": "Journal",
  "title": "Your Verified Paper Title",
  "authors": [
    { "name": "Your Name", "self": true, "coFirst": true },
    { "name": "Collaborator", "coFirst": true }
  ],
  "featuredRank": 1,
  "image": "/assets/images/publications/your-paper.svg",
  "imageAlt": "A concise explanation of the scientific figure",
  "summary": "One sentence explaining the contribution.",
  "keywords": ["Topic A", "Topic B"],
  "links": {
    "Journal": "https://publisher.example/paper",
    "Project": "/projects/your-project/",
    "GitHub": "https://github.com/yourusername/your-project"
  },
  "bibtex": "@article{...}"
}
```

Allowed `type` values should match your filter buttons, for example `Journal`, `Conference` and `Preprint`. Only use `featuredRank` when the entry has a meaningful image.

### Projects and news

Project `type` controls the index filters. Current examples are `Dataset`, `Method` and `Research map`. The slug generated by the script must match the filter button's `data-project-filter`.

News should be selective. Three or four important signals are stronger than a long activity log.

## 4. Curate the homepage

The library and atlas are data-driven. The homepage is intentionally editorial: update the feature cards in `index.html` so the order, visual rhythm and amount of detail reflect the importance of each work.

Good defaults:

- 3–5 full-width featured publications;
- at most 2 compact visual cards;
- a concise additional-publications list;
- 2 strong project stories;
- no duplicated biography section below the hero.

For each image, use the same source for `.paper-ambient` and `.paper-artwork`. The ambient layer creates the integrated blur while the artwork remains legible.

## 5. Add project pages

Duplicate one of these directories:

- `projects/featured-project/` for a method or system;
- `projects/medical-ai/` for a dataset or benchmark.

Rename the directory, update its metadata and add the new URL to `research.json`. Keep the story structure:

1. problem and motivation;
2. core contribution;
3. evidence and limitations;
4. paper, code, data and demo links;
5. accessible figure captions and alternative text.

## 6. Replace visuals responsibly

- Prefer SVG, WebP or AVIF.
- Keep raster images reasonably compressed and avoid multi-megabyte figures on the homepage.
- Crop for meaning, not decoration.
- Remove publisher marks unless you have permission to redistribute them.
- Write alternative text that explains what the visual communicates.
- Decorative ambient images should use `alt=""` and `aria-hidden="true"`.

## 7. Add a CV

Place the PDF in `assets/docs/`, then add a download link:

```html
<a href="/assets/docs/your-name-cv.pdf" download>Download CV ↓</a>
```

Include a version date in the label and update it whenever the file changes.

## 8. Tune the visual system

Start with the custom properties at the top of `assets/css/cosmic.css`. Keep sufficient color contrast and test both dark displays and ordinary laptop screens.

Avoid adding a new card, border or animation merely to fill space. Spatialfolio works best when motion explains a research concept and when light/dark section changes separate information layers.

## 9. Customize the Canvas scene

Read [CODEX_VISUALS.md](CODEX_VISUALS.md). Preserve:

- the `data-spatial-world` canvas selector;
- mode names or their corresponding HTML buttons;
- `canvas.spatialWorld`, `setMode()` and pointer interaction behavior;
- reduced-motion handling;
- mobile performance and resize behavior;
- readable text content outside the canvas.

## 10. SEO and sharing

- Replace all `yourusername.github.io` URLs.
- Update `robots.txt` and `sitemap.xml`.
- Replace `assets/images/social-preview.svg` with a 1200×630 PNG or WebP if your target platform does not preview SVG.
- Use a unique title and description on every page.
- Set the GitHub repository About text and topics from the README.
- Link the portfolio from your GitHub profile, Scholar profile, ORCID and CV.

## 11. Attribution

Keep the visible link to:

```text
https://github.com/zhuqinfeng1999/interactive-academic-portfolio
```

It is included in every sample footer. You may change the wording and typography, but not remove, hide or obstruct the link.

## 12. Validate and deploy

```bash
npm run validate
npm run serve
```

Review at desktop, tablet and mobile widths. Test keyboard navigation, the command palette, publication search, every project filter, every Canvas mode, all internal links and the reduced-motion preference.

Then deploy from the repository root through GitHub Pages.
